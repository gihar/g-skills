# Daily News Digest

## Overview

Создание структурированных новостных сводок на русском языке с обязательными ссылками, фильтрацией источников и факт-чекингом. Основной формат — компактный Telegram-ready дайджест, который можно отправить одним сообщением.

Главный принцип: **сразу к новостям, без служебных вступлений, без воды, с кликабельными источниками и проверенными фактами**.

## ⚡ Перед каждым запуском

**Обязательно перечитать этот файл целиком.** Даже если кажется, что правила известны — перечитай актуальный `SKILL.md`. Правила менялись; старая версия из памяти может быть неверной.

## When to Use

Использовать, когда пользователь просит:

- новости дня;
- ежедневную сводку;
- morning briefing;
- обзор прессы;
- «что происходит сегодня / в мире / в России»;
- краткий Telegram-дайджест;
- новости по AI/LLM/агентам, если явно просит AI-дайджест.

Не использовать для:

- глубокой аналитики на 10+ страниц;
- расследований;
- long-form отраслевых отчётов;
- юридически значимых справок;
- задач, где нужна не сводка, а полный research report.

## 🚨 Чеклист перед публикацией

- [ ] Режим выбран: `general` или `ai_focus`.
- [ ] Для `general`: есть 5 обязательных категорий — 💰 экономика, 🔬 наука, 🤖 технологии, ⚔️ конфликты, ⚽ спорт.
- [ ] Законодательство / регулирование добавлено отдельным блоком, если найдена значимая свежая новость.
- [ ] Для `ai_focus`: есть 4–5 AI-категорий из раздела «AI/LLM-focused режим».
- [ ] Каждая новость проверена по 2 независимым источникам.
- [ ] В итоговом тексте у каждой новости есть 1–2 кликабельные ссылки в формате `📎 [Название](url)`.
- [ ] Не используется слово «источники» как заголовок или подпись к ссылкам.
- [ ] Запрещённые домены исключены: `interfax.ru`, `ria.ru`, `rt.com`, `russian.rt.com`, `tass.ru`.
- [ ] Спорт: конкретный результат/событие, а не расписание будущих матчей.
- [ ] Нет вступлений типа «Вот главные новости» — сразу первый блок.
- [ ] Нет разделителей `───`, `---`, `***`; между блоками только пустая строка.
- [ ] Итоговая сводка ≤3500 символов, чтобы влезла в одно Telegram-сообщение.
- [ ] Последняя строка ровно одна: `📝 Факт-чекинг: ✅ N/M`.

## Modes

### 1. `general` — обычная ежедневная сводка

Использовать по умолчанию, если пользователь просто просит новости / сводку / briefing.

Обязательные блоки:

1. 💰 Экономика
2. ⚖️ Законодательство — только если есть значимая новость
3. 🔬 Наука
4. 🤖 Технологии
5. ⚔️ Конфликты
6. ⚽ Спорт

### 2. `ai_focus` — новости AI / LLM / AI-агентов

Использовать, если пользователь явно просит новости AI, LLM, AI-агентов, AI engineering, моделей, инструментов разработки с AI.

Рекомендуемые блоки:

1. 🤖 AI/LLM модели
2. 🧠 AI-агенты и agent workflows
3. 🛠 Инструменты разработки / AI engineering
4. 🏢 Бизнес и рынок AI
5. 📚 Исследования и open-source
6. ⚖️ Регулирование AI — если есть значимая свежая новость

Для `ai_focus` не нужно искусственно включать спорт, конфликты и общую экономику, если пользователь просит именно AI-дайджест.

## Search Process

### General mode — максимум 5 поисковых запросов

Выполнить по одному `web_search` на категорию:

1. `Россия экономика новости сегодня`
2. `наука новости сегодня открытие исследование`
3. `технологии ИИ новости сегодня`
4. `мировой конфликт геополитика сегодня`
5. `спорт результаты сегодня`

Дополнительный законодательный поиск делать только если он заменяет или уточняет найденный технологический/экономический блок:

- `закон законопроект регулирование Россия сегодня`

Свежесть: сначала день; если результатов мало или они нерелевантны — расширить до недели.

### AI-focused mode — максимум 5 поисковых запросов

1. `AI LLM model release today OpenAI Anthropic Google Meta`
2. `AI agents coding agents workflows news today`
3. `AI developer tools SDK IDE agents news today`
4. `AI regulation law policy today`
5. `AI research paper open source model today`

Если русскоязычные результаты слабые — искать на английском и писать итог по-русски.

## Source Policy

### Запрещённые источники

Никогда не использовать как ссылку и не считать подтверждением:

- `interfax.ru`
- `ria.ru`
- `rt.com`
- `russian.rt.com`
- `tass.ru`

Если новость доступна только на запрещённых доменах — лучше пропустить новость или выбрать другую.

### Приоритет источников для general mode

Высокий приоритет:

- `vedomosti.ru`
- `kommersant.ru`
- `rbc.ru`
- `bbc.com`
- `reuters.com`
- `theguardian.com`
- `meduza.io`

Средний приоритет:

- крупные профильные издания;
- официальные сайты организаций;
- пресс-релизы компаний, если они подтверждаются независимым источником;
- спортивные федерации / лиги / клубы для результатов.

### Приоритет источников для AI-focused mode

Высокий приоритет:

- официальные блоги компаний: OpenAI, Anthropic, Google DeepMind, Meta AI, Microsoft, NVIDIA, Mistral, xAI и т.п.;
- arXiv / Papers with Code / GitHub для research/open-source;
- The Verge, TechCrunch, VentureBeat, The Information, Reuters, Bloomberg, Financial Times — если доступны;
- документация или changelog продукта для SDK/tooling.

Важно: официальный блог компании может быть **первичным источником**, но для факт-чекинга желательно найти независимый вторичный источник или raw artifact: paper, repo, docs, benchmark page.

## Fact-checking

Каждая новость до публикации должна быть проверена по **2 независимым источникам**.

Проверять:

- дату публикации;
- имена людей и организаций;
- цифры, проценты, суммы, результаты матчей;
- что событие уже произошло, а не только ожидается;
- что второй источник не является простым перепостом первого.

В итоговом сообщении можно показать 1–2 ссылки. Если показывается одна ссылка, вторая всё равно должна быть использована для проверки при подготовке.

Финальная строка:

```text
📝 Факт-чекинг: ✅ N/M
```

Где:

- `N` — количество подтверждённых новостей;
- `M` — количество новостей в итоговой сводке.

После этой строки ничего не добавлять.

## Selection Rules

Выбирать максимум 1 новость на категорию. Исключение: 2 новости в одной категории только если событие чрезвычайно значимое и общий лимит 3500 символов не нарушен.

Приоритет новостей:

1. изменения законодательства / регулирования;
2. решения с последствиями для рынка, безопасности, пользователей;
3. конкретные цифры, статистика, финансовые результаты;
4. релизы продуктов, моделей, SDK, важных open-source проектов;
5. общие заявления — только если нет более конкретных событий.

Не включать:

- слухи без подтверждения;
- кликбейт;
- «планируется / может произойти», если нет конкретного решения;
- устаревшие новости, выдаваемые за сегодняшние;
- спорт без результата или конкретного события.

## Output Format

Писать сводку сразу, без вступления.

Формат блока:

```text
💰 Экономика

• Одно событие в 1–2 предложениях. Нужны конкретные факты, цифры, даты или имена.
  📎 [Название](https://example.com) / [Название 2](https://example.com)
```

Правила форматирования:

- названия разделов — отдельной строкой;
- одна bullet-новость на блок;
- ссылки идут на следующей строке после новости;
- использовать `📎 [Название](url)`, не писать «источники:»;
- между блоками — пустая строка;
- не использовать таблицы;
- не использовать markdown-разделители;
- итог ≤3500 символов.

## Sources Cache

Если существует файл `sources-cache.json`, использовать его для ускорения проверки и предотвращения повторного использования одних и тех же материалов.

Рекомендуемое расположение по умолчанию:

```text
~/.hermes/cache/daily-news/sources-cache.json
```

Если задача выполняется в проектной директории или cron job имеет свой `workdir`, можно использовать локальный файл:

```text
./sources-cache.json
```

Формат:

```json
{
  "version": 1,
  "updated_at": "2026-06-02T09:00:00+03:00",
  "items": {
    "https://example.com/news/item": {
      "checked_at": "2026-06-02T09:00:00+03:00",
      "domain": "example.com",
      "title": "News title",
      "category": "technology",
      "verdict": "usable"
    }
  }
}
```

Правила кеша:

- если URL проверялся менее 7 дней назад и `verdict = usable`, можно не извлекать его повторно, но дату новости всё равно проверить по сниппету/странице при необходимости;
- если `verdict = forbidden` или домен запрещён — не использовать;
- после подготовки сводки обновить `checked_at` для реально проверенных URL;
- не кешировать секреты, cookie, paywall tokens или приватные URL.

## Common Pitfalls

1. **Ответ без ссылок.** Любая новость без кликабельного URL считается браком.
2. **Использование запрещённых доменов.** Нельзя использовать даже как второй источник факт-чекинга.
3. **Смешивание категорий.** В general mode наука и технологии — разные блоки.
4. **Спорт как расписание.** Нужен результат или конкретное событие.
5. **Слишком длинный текст.** Если больше 3500 символов — сокращать описания, а не разбивать на второе сообщение.
6. **Служебные вступления.** Не писать «собираю», «вот сводка», «поехали» — сразу первый раздел.
7. **Один первоисточник под видом двух.** Перепечатка пресс-релиза не является независимым подтверждением.
8. **Слово «источники».** Для Telegram-сводок пользователя ссылки должны быть кликабельными, но без подписи «источники».
9. **Старая версия правил из памяти.** Каждый запуск начинается с чтения актуального `SKILL.md`.

## Verification Checklist

Перед финальным ответом проверить:

- [ ] skill был перечитан в текущем запуске;
- [ ] выбран правильный режим;
- [ ] все обязательные категории покрыты или явно заменены смежной свежей темой;
- [ ] запрещённых доменов нет;
- [ ] у каждой новости есть ссылка;
- [ ] каждая новость подтверждена 2 независимыми источниками;
- [ ] даты свежие;
- [ ] факты и цифры не противоречат источникам;
- [ ] итог ≤3500 символов;
- [ ] последняя строка — только `📝 Факт-чекинг: ✅ N/M`.
