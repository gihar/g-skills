# Crocotime: отчёт по отработанному времени

Формирует структурированный месячный `.xlsx` по API Crocotime в формате эталона:

- сводный лист с группировкой по департаментам;
- персональный лист каждого сотрудника;
- приход/уход, норма, отработанное время, выполнение нормы, переработка;
- отвлечения, продуктивное время, время без компьютера;
- 24-часовая шкала активности: зелёный — работа за компьютером, серый — промежуток между приходом и уходом без активности;
- скрытые листы `Данные` и `Параметры` для аудита источника и расчётов.

Исходный Excel-эталон был набором PNG-скриншотов. Этот скилл воспроизводит его содержание и визуальную логику нормальными ячейками, формулами и фильтрами.

## Обязательные входы

1. Месяц `YYYY-MM`.
2. Базовый URL Crocotime Web API — параметр `--base-url` или `CROCOTIME_URL`.
3. Токен Crocotime в переменной окружения `CROCOTIME_TOKEN` (или другой, указанной через `--token-env`). **Не записывать токен в команду, отчёт, логи или SKILL.md.**
4. Путь результата в активном workspace.

Если URL или токен неизвестны, запросить их у пользователя. Токен создаётся в Crocotime: **Конфигурация → Токены**.

## Постоянная настройка окружения Hermes

Предпочтительный способ — через CLI Hermes. Сначала скопировать фактический токен из Crocotime (**Конфигурация → Токены**), затем в терминале выполнить:

```bash
hermes config set --force CROCOTIME_URL 'https://адрес-crocotime/'
read -rsp 'Вставьте токен Crocotime: ' CROCOTIME_TOKEN; echo
hermes config set CROCOTIME_TOKEN "$CROCOTIME_TOKEN"
unset CROCOTIME_TOKEN
hermes gateway restart
```

Когда терминал покажет `Вставьте токен Crocotime:`, вставить **само скопированное значение токена** и нажать Enter. При вводе символы не отображаются — это нормально. Не вводить буквальный текст `секретный-токен` или `...`: это были только обозначения места для реального значения.

Hermes автоматически размещает значения правильно:

- `CROCOTIME_URL` — пользовательская обычная настройка в `config.yaml`;
- `CROCOTIME_TOKEN` — секрет в `.env`, потому что имя заканчивается на `_TOKEN`.

Генератор сначала проверяет переменные процесса, а если их нет — безопасно читает настройки активного профиля через `hermes config get`. Поэтому вручную выполнять `export` перед каждым отчётом не нужно.

Пути активного профиля можно проверить так:

```bash
hermes config path
hermes config env-path
```

Для профиля `default` это обычно `~/.hermes/config.yaml` и `~/.hermes/.env`. Для именованного профиля использовать `hermes --profile <name> config ...`; значения сохранятся в каталоге соответствующего профиля. Не запускать `hermes config get CROCOTIME_TOKEN`: команда напечатает секрет в терминал.

После изменения окружения обязательно начать новый CLI-сеанс или перезапустить gateway/WebUI. Текущий уже запущенный процесс не получает новые значения автоматически.

## Подготовка зависимостей

```bash
python3 -c "import openpyxl; print(openpyxl.__version__)"
command -v libreoffice || command -v soffice
```

Нужны Python 3.11+ и `openpyxl`. Для обязательного пересчёта формул нужен LibreOffice.

## Запуск

Скрипт находится в `scripts/crocotime_report.py`.

```bash
export CROCOTIME_URL='https://crocotime.example.ru/'
export CROCOTIME_TOKEN='...'
python3 scripts/crocotime_report.py \
  --month 2026-07 \
  --output '/absolute/path/отработанное_время_июль_2026.xlsx'
```

Фильтры можно повторять:

```bash
python3 scripts/crocotime_report.py \
  --month 2026-07 \
  --department-id 15 \
  --employee-id 101 \
  --employee-id 205 \
  --output '/absolute/path/report.xlsx'
```

Дополнительные параметры:

- `--app-version` или `CROCOTIME_APP_VERSION` — версия сервера для обратной совместимости API;
- `--timezone Europe/Moscow` — часовой пояс отчёта;
- `--timeout 60` — таймаут одного HTTP-запроса;
- `--token-env NAME` — имя переменной окружения с токеном.

Если одновременно заданы фильтры департамента и сотрудников, применяется их пересечение.

## Алгоритм

1. Получить сотрудников через `api_employees`.
2. Получить дерево подразделений через `api_departments`; фильтр департамента включает вложенных сотрудников.
3. Получить месячную сводку через `api_employee_activity`.
4. Для каждого сотрудника получить временные интервалы через `api_window_switch_train`.
5. Для каждого календарного дня получить:
   - статистику — `api_employee_activity`;
   - приход/уход — `api_employee_work_periods`;
   - норму и статусы — `api_employee_working_day_schedule`.
6. Не добавлять пустые дни без активности и без отпуска/больничного/отгула/праздника.
7. Сформировать XLSX и проверить его встроенной проверкой скрипта.
8. Обязательно пересчитать формулы LibreOffice и убедиться, что ошибок нет.

## Обязательная проверка

```bash
python3 /home/user/.hermes/skills/productivity/xlsx/scripts/recalc.py '/absolute/path/report.xlsx' 60
```

Требуемый результат:

- `status: success`;
- `total_errors: 0`;
- число видимых листов = число сотрудников + 1 сводный лист;
- файл открывается через `openpyxl` и имеет ненулевой размер.

После пересчёта выборочно проверить:

- 2–3 значения отработанного времени;
- проценты выполнения нормы;
- знак переработки;
- даты и приход/уход на персональном листе;
- наличие зелёных/серых сегментов шкалы.

## Семантика полей

- **Отработанное** ← `summary_time`.
- **Норма** ← `norm`.
- **Переработка** ← `summary_time - norm`.
- **Продуктивное** ← `permitted_time`.
- **Отвлечения** ← `forbidden_time`.
- **Без компьютера** ← `unknown_time`; если поле отсутствует — `summary_time - permitted_time - forbidden_time`.
- `begin`/`end` — секунды от начала локального дня; `-1` означает, что время не определено.
- отпуск, больничный, отгул и праздник берутся из дневного расписания.

## Ограничения и правила

- Временная шкала показывает наличие компьютерной активности по `api_window_switch_train`, но не раскрашивает конкретные приложения по продуктивности: API из приложенной документации не возвращает классификацию каждого оконного интервала.
- Не подменять отсутствующие данные догадками. Неизвестные приход/уход оставлять пустыми.
- Не публиковать и не сохранять токен. В скрытый лист `Параметры` записывается только URL, период и время формирования.
- Результат сохранять в активный workspace, а не в `/home/user`.
- При ошибке API выводить реальную ошибку и не создавать правдоподобный фиктивный отчёт.
